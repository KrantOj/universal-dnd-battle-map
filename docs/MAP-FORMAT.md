# Формат карты (`*.map.json`)

Идентификатор формата: `vestfalia-battlemap/1`. Идентификатор сохранён для совместимости с уже созданными картами; менять его нельзя.

Карта — это JSON-файл `<имя>.map.json` и картинка, на которую он ссылается полем `image`. Картинка рисуется в поле
карты, сетка накладывается приложением. Пример в конце; эталон — `tests/fixtures/demo.map.json`.

## 1. Верхний уровень

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `format` | string | да | `"vestfalia-battlemap/1"` |
| `name` | string | нет | название для показа (`title`); ключ сцены — имя файла |
| `image` | string | нет | имя файла картинки в той же папке (например `"<имя> (VTT).png"`) |
| `image_grid` | `{x,y,width,height}` | нет | px: где находится клетка A1 внутри картинки, и полный размер картинки (см. §6) |
| `resolution` | object | **да** | `map_size`, `pixels_per_grid`; `map_origin` всегда `{0,0}`, приложением не используется |
| `resolution.map_size` | `{x: cols, y: rows}` | **да** | размер сетки в клетках |
| `resolution.pixels_per_grid` | int | нет | пикселей на клетку, по умолчанию 70 |
| `feet_per_cell` | int | нет | футов в клетке, по умолчанию 5 |
| `layers` | object | нет | слои клеток (§3); отсутствующий слой заменяется значением по умолчанию |
| `line_of_sight` | `Point[][]` | нет | стены (§4) |
| `portals` | object[] | нет | двери (§5) |
| `labels` | object[] | нет | подписи (§6) |
| `lights` | object[] | нет | источники света; приложением **не используется**, зарезервировано |
| `coords`, `height_reference`, `darkness` | — | нет | справочные поля, приложением не читаются |

Без `resolution.map_size` файл отклоняется как «не файл карты».

## 2. Координаты

- **Клетка** — пара целых `(x, y)`: `x` — столбец от 0, `y` — строка от 0. Диапазон: `0 ≤ x < cols`, `0 ≤ y < rows`.
- **Имя клетки** (A1-нотация, `cellName`): `x` → буквы `A..Z`, затем `AA..`; `y` → номер с 1. `(0,0)` = `A1`, `(3,5)` = `D6`, `(26,0)` = `AA1`.
- **Углы клеток** — целые точки. Клетка `(x,y)` занимает квадрат `[x, x+1] × [y, y+1]`; её центр — `(x+0.5, y+0.5)`.
- Стены (`line_of_sight`) и двери (`portals`) задаются в **координатах углов** (в клетках). Значения могут быть дробными.
- **Пиксели картинки**: клетка `(x, y)` начинается в пикселе
  `image_grid.x + x * ppg`, `image_grid.y + y * ppg` и занимает квадрат `ppg × ppg`. Размер картинки должен совпадать
  с `image_grid.width × image_grid.height`, иначе приложение выдаёт предупреждение.
- Высота (`elevation_ft`) — в футах относительно уровня пола (`0 фт = уровень пола`).

## 3. `layers`

Каждый слой — двумерная сетка `layers.<имя>[y][x]`, размер `rows × cols` (то есть `map_size.y` строк по `map_size.x` значений).
Слои параллельны: значение клетки `(x,y)` берётся из `layers.<имя>[y][x]` для каждого слоя.

| Слой | Тип | По умолч. | Использование |
|---|---|---|---|
| `terrain` | string | `""` | описание местности; для воды ищется подстрока `water` (без учёта регистра) |
| `elevation_ft` | int | `0` | высота клетки; не влияет на проходимость и стоимость; показывается в статус-строке, возвращается из `findPath` (`elevFrom`, `elevTo`) |
| `difficult` | 0/1 | `0` | труднопроходимая местность: ×2 стоимость |
| `hazard` | null / string | `null` | `"hole"` — яма, клетка непроходима; другие значения пока игнорируются |
| `obstacle` | 0/1 | `0` | препятствие (стена-блок внутри клетки): клетка непроходима, но видна и не блокирует обзор |
| `walkable` | 0/1 | `1` | `0` — клетка не для ходьбы; если `terrain` содержит `water`, это плавание, иначе непроходима |

## 4. Проходимость (`cellRule`)

Правило применяется в порядке таблицы; первое совпавшее условие решает. Выход за сетку — всегда непроходим.

| Условие | Результат | Множитель стоимости |
|---|---|---|
| вне сетки | блок | — |
| `obstacle == 1` | блок | — |
| `hazard == "hole"` | блок | — |
| `walkable == 0` и `terrain` содержит `water` | проходимо (плавание) | ×2 |
| `walkable == 0`, иначе | блок | — |
| `difficult == 1` | проходимо | ×2 |
| прочее | проходимо | ×1 |

Множители не складываются: если клетка одновременно водная и труднопроходимая, стоимость ×2, а не ×4.
Стоимость шага: 5 фт × множитель клетки, в которую вошли (во вторую диагональ в режиме `5-10-5` — 10 фт × множитель).

## 5. Стены и двери

### `line_of_sight` (стены)
Массив полилиний. Полилиния — массив точек `{x, y}` в координатах углов. Соседние точки образуют отрезок.

```json
"line_of_sight": [
  [{"x": 2, "y": 2}, {"x": 13, "y": 2}, {"x": 13, "y": 9}],
  [{"x": 2, "y": 2}, {"x": 2, "y": 5}]
]
```

Стена блокирует движение и обзор. Диагональ запрещена, если стена перекрывает оба ортогональных «угла» шага
(срезать угол стены нельзя).

### `portals` (двери)
```json
{ "position": {"x": 2, "y": 5}, "size": [1, 1], "dir": "v", "open": false }
```

| Поле | Смысл |
|---|---|
| `position` | левый верхний угол двери (угол клетки) |
| `size` | `[w, h]`, по умолчанию `[1, 1]` |
| `dir` | `"h"` — горизонтальная дверь: отрезок `(x, y) → (x + w, y)`; `"v"` — вертикальная: `(x, y) → (x, y + max(w, h))` |
| `open` | начальное состояние: `true` — открыта. Текущее состояние хранится в сцене (`doors[i]`) |

- Индекс двери `i` в массиве `portals` связывает её с `scene.doors[i]`.
- Закрытая дверь блокирует движение и обзор, как стена. Открытая — не блокирует.
- Дверь рисуется доской по своему отрезку; игрокам показывается, если открыта хотя бы одна соседняя клетка.

## 6. Картинка и подписи

### `image` и `image_grid`
- `image_grid` опционален. Если его нет, принимается `{x:0, y:0, width: cols*ppg, height: rows*ppg}`.
- Картинка — рамка с заголовком и легендой вокруг сетки. Рамка вне сетки никогда не закрывается туманом.
- Если размер картинки не совпадает с `image_grid`, карта открывается с предупреждением «картинка не совпадает с сеткой».

### `labels` (подписи)
```json
{ "text": "Пруд", "x": 5, "y": 3, "size": 0.36, "kind": "area" }
```
- `x`, `y` — центр текста в координатах клеток (`text-anchor: middle`, `baseline: central`).
- `size` — высота шрифта в клетках. По умолчанию: `0.42` для `kind: "area"`, `0.26` для `kind: "object"`.
- `kind` — `"area"` (название местности) или `"object"` (объект). Влияет на умолчания и стиль (курсив у `area`).
- Подписи рисуются приложением, а не картинкой. Показ раздельно управляется мастером для себя и для игроков.

## 7. Минимальный пример

Карта 3×2 с водой, труднопроходимой клеткой, стеной и дверью.

```json
{
  "format": "vestfalia-battlemap/1",
  "name": "Пример",
  "image": "example (VTT).png",
  "image_grid": { "x": 0, "y": 0, "width": 210, "height": 140 },
  "resolution": { "map_origin": { "x": 0, "y": 0 }, "map_size": { "x": 3, "y": 2 }, "pixels_per_grid": 70 },
  "feet_per_cell": 5,
  "layers": {
    "terrain":      [["stone", "stone", "dirt"], ["stone", "water", "dirt"]],
    "elevation_ft": [[0, 0, 10], [0, 0, 0]],
    "difficult":    [[0, 0, 0], [0, 1, 0]],
    "hazard":       [[null, null, null], [null, null, null]],
    "obstacle":     [[0, 0, 0], [0, 0, 0]],
    "walkable":     [[1, 1, 1], [1, 0, 1]]
  },
  "line_of_sight": [
    [{ "x": 1, "y": 0 }, { "x": 1, "y": 1 }]
  ],
  "portals": [
    { "position": { "x": 2, "y": 0 }, "size": [1, 1], "dir": "v", "open": false }
  ],
  "labels": [
    { "text": "Пруд", "x": 1.5, "y": 1.5, "size": 0.36, "kind": "area" }
  ],
  "lights": []
}
```

Клетка `B2` (`(1,1)`) — вода и труднопроходимая одновременно: вход в неё стоит ×2 (не ×4).
Стена (`x=1`, `y` от 0 до 1) стоит между `A1` и `B1`. Закрытая дверь (`x=2`, `y` от 0 до 1) стоит между `B1` и `C1`.

## 8. Библиотека токенов (`vestfalia-tokens/1`)

Файл `library.tokens.json` в папке данных кампании. Формат:
```json
{ "format": "vestfalia-tokens/1", "tokens": [ { "lid": "t1a2b3", "updated": 1763000000000, "name": "…", "label": "ИВ", "color": "#3fb950", "kind": "pc", "size": 1, "speed": 30, "vision": 60, "image": null, "hidden": false, "category": "", "maxHp": 20, "ac": 15, "team": 0, "initMod": 2 } ] }
```
- `lid` — уникальный id шаблона; при слиянии с другой копией побеждает запись с большим `updated`.
- Поля шаблона — поля токена без `x`, `y`, `moved`, `status`, `init`, `hp`. Токен на карте хранит `lid` своего шаблона.
- Картинка `image` — dataURL или `null`.
- Тот же формат используется в legacy-файле `Библиотека токенов.vtt.json` в папке карт (читается для совместимости).
