# Dice skins (3D)

A skin changes how the 3D dice look: body colour and material, texture, number colour and glow. A skin is **a folder with a `skin.json` file and a few images**. No code, so the files are safe to share.

Choose a skin in **Settings → Dice (3D)**. Players see the selected skin. There is also a "Roll a sample" button.

## Where to put it

The **"Open skins folder"** button (Settings → Dice) opens the right folder. Each skin gets its own subfolder:

```
dice-skins/
  My stone/
    skin.json
    body.png
    body_normal.png
```

Add a folder, press **"Refresh list"**, and the skin appears under "Custom". Folders without a readable `skin.json` are skipped. A ready sample: [docs/dice-skin-example](dice-skin-example/) (copy it into the skins folder).

## skin.json

Every field is optional; missing ones fall back to the "Classic" look. Invalid values are replaced by defaults.

```json
{
  "format": "udbm-dice-skin/1",
  "name": { "ru": "Камень", "en": "Stone" },
  "body": { "color": "#ffffff", "metalness": 0.05, "roughness": 0.8,
            "map": "body.png", "normalMap": "body_normal.png", "roughnessMap": "body_rough.png",
            "mapScale": 1.0, "normalScale": 1.0 },
  "edges":   { "color": "#c9c0a8", "opacity": 0.5 },
  "numbers": { "color": "#ffe9a8", "outline": "#1a1208", "glow": "#ff9b2e", "size": 1.0, "font": "Georgia" }
}
```

| Field | Meaning | Range |
|---|---|---|
| `name` | List name: string or `{ "ru", "en" }` | up to 40 chars |
| `body.color` | Body colour; with a `map` it is only a **tint** (multiplied by the image), default is then white | `#rrggbb` |
| `body.metalness` / `body.roughness` | 0 = stone/bone, 1 = metal / 0.05 = mirror gloss, 1 = matte | 0…1 / 0.05…1 |
| `body.map` | Colour (albedo) image | PNG/JPG/WebP, file name only, no subfolders |
| `body.normalMap` | Normal map, OpenGL format (Blender default) | same |
| `body.roughnessMap` | Greyscale roughness map (multiplied by `roughness`) | same |
| `body.mapScale` | Texture scale: higher = finer pattern | 0.1…10 |
| `body.normalScale` | Relief strength; **negative flips it** (for DirectX normal maps) | −5…5 |
| `edges.color`, `edges.opacity` | Thin edge lines | colour, 0…1 |
| `numbers.color`, `numbers.outline`, `numbers.glow` | Number colour, outline, glow colour (empty = no glow) | `#rrggbb` |
| `numbers.size`, `numbers.font` | Number size; font (must be installed in Windows) | 0.6…1.3 |

Limits: `skin.json` up to 64 KB, each image up to 6 MB (512×512 or 1024×1024 is plenty).

The models have no UV map, so the app projects the texture **onto each face separately**. The face centre lands in the middle of the texture, so for `mapScale` up to about 1.4 the texture does **not** need to be seamless; use a seamless texture for larger values.

## Making a skin in Blender

1. **Colour and gloss.** In Material Preview adjust a Principled BSDF: `Metallic` → `body.metalness`, `Roughness` → `body.roughness`, colour via the Hex tab (`2B3A56` → `"#2b3a56"`). The look is close to Blender but not identical; check with "Roll a sample".
2. **Texture.** Either download a CC0 PBR set (ambientCG / Poly Haven, 1K PNG: `Color` → `body.png`, `NormalGL` → `body_normal.png`, `Roughness` → `body_rough.png`), or build a procedural material on a Plane in Cycles and bake it: add an unconnected Image Texture node (new 1024×1024), Render Properties → Bake → *Diffuse* with only *Color* (turn off Direct/Indirect), Bake, then Image Editor → Image → Save As `body.png`. Repeat with *Normal* (`body_normal.png`) and *Roughness* (`body_rough.png`). Or paint directly in the Texture Paint workspace.
3. **Assemble and test.** Put `skin.json` and the images in a folder, then Settings → Dice (3D) → Refresh list → pick it → Roll a sample. Do not paint numbers on the texture; the app draws them.

## Troubleshooting

Not in the list: invalid JSON or no `skin.json`. Texture missing: wrong file name/type, over 6 MB, or in a subfolder. Too dark: with a texture `body.color` multiplies it, use `"#ffffff"`. Relief looks inverted: `"normalScale": -1`. If a skin fails to load the app falls back to "Classic" and writes the reason to the log.

Custom die shapes and number images are not supported in format version 1.

The sample skin is generated by `node scripts/make-example-skin.js`.
